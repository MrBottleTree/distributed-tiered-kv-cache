- Finish the opt-in attention probe's **hardware verification** (implementation and CPU scoring check are in `PROGRESS_REPORT.md`): install this package on Machine A, run `python -m attention_probe.run --probe --enforce-eager` with one GPU and no remote backend, and confirm four nonzero per-step records, each query head's window mass sums to about 1, and generated output matches a probe-off run. ### Next task — Per-head implementation plan

**Scope:** independently place, quantize, prefetch, and evict **one layer's one KV head for a token chunk**, with K/V together. Keep 256-token chunks and shorter final chunks. For GQA, segment shared KV heads, not individual query heads. vLLM's GPU layout/attention kernel and the decision policy remain unchanged; attention-guided decisions stay in Milestone 3.

**RedKnot reference:** reviewed `RedKnot-vLLM` at [`4eb99dbc`](https://github.com/rednote-machine-learning/RedKnot/tree/4eb99dbc0f818cc16be9d535f7604f85ed0d6dfd/vllm_redknot). Follow its [SegPaged design](https://github.com/rednote-machine-learning/RedKnot/blob/4eb99dbc0f818cc16be9d535f7604f85ed0d6dfd/vllm_redknot/core/segpaged_v2/page_table.py): visible positions → `(layer, KV head, segment)` table → physical storage. However, these core modules are [extracted, not runtime-integrated](https://github.com/rednote-machine-learning/RedKnot/blob/4eb99dbc0f818cc16be9d535f7604f85ed0d6dfd/docs/CORE_EXTRACTION.md). Its active MHA adapter caches local-head K/V **and attention outputs**, reuses clean local rows, and computes global/boundary rows; this is not our tiered KV-only pipeline. Its [runner](https://github.com/rednote-machine-learning/RedKnot/blob/4eb99dbc0f818cc16be9d535f7604f85ed0d6dfd/vllm_redknot/runner.py) rejects Mistral, quantized weights, and KV connectors, and its README leaves full-model validation pending. Reuse the small storage/GQA/transaction patterns, not the plugin or its performance claims; retain upstream attribution/license notices in any adapted helpers.

1. **Baseline/configuration.** Preserve A's non-per-head `37d143c` on `vishrut-addition` (`7bf1a6f` uses FP16 weights). B's `main` is at `7d52118` with uncommitted service/setup fixes: snapshot those separately before editing overlapping files. Make separate feature commits in both repositories and record paired SHAs. Add `extra_config.grpc_granularity: chunk|head` to `lmcache_config.yaml`, default `chunk`; preserve legacy RPCs/behavior. Keep model, FP16 GPU KV, prompts, alpha, and placement bands fixed. Use separate cache namespaces/directories, not migration of old files.

2. **A: RedKnot-style logical head segments.** Add `LMCache/lmcache/v1/storage_backend/head_segments.py` with small `HeadVisiblePlan`, `HeadSegment`, and `HeadSegmentTable` records, plus `make_segment_id()`, `split_chunk()`, `assemble_chunk()`. Following `core/segpaged_v2/{visible_plan,page_table}.py`, map `(namespace,parent,layer,KV-head)` to original token positions and storage handles; expose `store_head_segment()`/`gather_segment()` through `grpc_backend.py`. In Milestone 2 every plan retains `[0,T)`; encode contiguous positions compactly, with an explicit-position schema available for later masked policies. Actual `KV_2LTD` shape is `[2,L,T,H_kv*D]`; derive topology from metadata and serialize contiguous `[2,T,D]` head segments. Persist a versioned descriptor with parent/worker identity, model/revision/layout/retention fingerprint, shape/dtype/format, token count, positions, and expected head IDs. Preserve context-sensitive LMCache keys: do not adopt RedKnot's non-prefix reuse or RoPE relocation. Adapt `ops.py::head_partition()`'s GQA mapping (`query_head // group_size → KV_head`), but do not enable local/global classification. Reassemble by coordinates, not response order. Start with single-GPU, non-layerwise, single-group FP16; reject other layouts.

3. **Protocol/atomic publication.** Extend B's `machine_b/proto/evicpress.proto`; synchronize A's copy and regenerate both stubs through the Makefiles, checking relative imports. Add byte-bounded batch store/lookup/retrieve/delete carrying descriptors and per-head status/tier; reuse repeated-ID prefetch. Add B `server/grpc_server.py` handlers, manager batch methods, and persistent `evicpress/head_groups.py` descriptors (B paths relative to `machine_b/`). Adapt `runtime.py`'s stage → validate → publish pattern: publish a parent only after all canonical head writes succeed; prevent capacity eviction of incoming heads during that commit. Validate all coordinates/positions/shape/dtype before exposing a reconstructed chunk. Adapt `cache.py::CacheManager.lease()`'s all-or-nothing protection across required heads, with RPC lease IDs/timeouts and cleanup on exception. Missing/corrupt heads return a whole-chunk miss; verify recomputation, including lookup/retrieve races.

4. **Physical storage separated from policy.** Mirror `core/segpaged_v2/storage.py`'s logical-handle/physical-storage separation, adapting it to our CPU allocator, B RAM/disk, and batched gRPC rather than installing RedKnot's GPU backend. Initially one contiguous head blob backs each 256-token head segment; their default 64-token internal pages are not required and must not change our scoring unit. Add byte-bounded `HeadSegmentCache`; in `storage_manager.py`, disable assembled-parent CPU write-back for head mode. Use a head-mode `MixedMemoryAllocator` path in `local_cpu_backend.py`, sharing A's RAM budget with staging. Do not copy `LocalPagedPool` unchanged: it grows without page reclamation; our handles need release/reuse, pinning, and failure cleanup. Apply `cache.py`'s admission-before-eviction/read-only ownership discipline. Reconcile B's ledger with actual A admissions/evictions; account for FP16 T1 bytes, not compressed B bytes. Keep process-local allocator handles out of persistent descriptors; reconstruct them on load.

5. **B: same policy per segment.** Update `evicpress/block.py`, `manager.py`, `tier_ram.py`, `tier_disk.py` to preserve head/parent metadata through copies, eviction, and restart. Retain `U = (alpha * quality - size_bytes / tier_bandwidth) * (access_count + 1) / (total_accesses + 1)` and placement bands. Compute `_compute_quality()` independently per serialized head: zlib ratio over at most 64 KiB, clamped `[0.1,1]`; this is compressibility, not attention/fidelity. Separate head access counters from logical parent requests; use parent requests for the denominator, avoiding batch-size inflation, and expose both statistics. Reuse `quantize.py`'s codecs with per-head K/V scales. Preserve inclusive T3 backing, quantized-copy prefetch, and dequantization on retrieval; recheck parent completeness after head eviction. Lossy backing cannot restore original FP16 values.

6. **Minimal tests/hardware gate.** Add one focused A `tests/` file for full-position scatter/gather, GQA group mapping (including nonconsecutive head IDs), short chunks, reordered replies, and missing-head rejection with a fake service; include it in `run_tests.py`. Use RedKnot's `tests/test_ops.py` as the head-order/GQA oracle, not as proof of our integration. Extend B's existing tests for batch completeness/rejection, leased-head eviction protection/release, restart, and one lossy round trip; run in B's checkout. On hardware, run gRPC/tensor smoke checks and cold/warm vLLM generation, forcing a head miss/tier pressure. FP16 restoration must be exact; compressed results need measured quality. Verify recomputation and memory limits. GPU/service checks remain pending; resolve Milestone 1's CUDA-extension blocker first.

7. **Reproducible comparisons.** Add `--granularity chunk|head` to `benchmarks/suite.py`/`run_tests.py`; update `make_a_config()`, preflight, metadata, and manifest profiles. Check B's capability; record both SHAs, topology, head/parent counters, bytes/RPCs, and actual tier/staging memory alongside scores/latency. Preserve frozen inputs. Compare FP16 first, then identical alpha/compression profiles and effective byte budgets; per-head scales also change quantization error. For local demonstration, manually start existing B on `127.0.0.1` with host RAM/disk in both modes: no new backend needed. T1/T2 share physical RAM; local results do not establish network performance. Keep local restart automation separate. After implementation, briefly update README/PROGRESS_REPORT and replace this section with remaining checks.

**Limit/next seam:** vLLM still needs all heads/layers for reuse; one unavailable head invalidates the chunk unless recovered from another tier. Do not copy `per_head_storage.py::expand_to_dense()`'s zero-padding into ordinary attention: omitted positions require a matching per-head mask/kernel to be safe. RedKnot-style sink/window/custom-position retention, direct per-head GPU scatter, sparse attention, and head-output reuse require a later explicit vLLM integration experiment; merely adding a segment table does not provide them or reduce HBM allocation. Keep Milestone 2's visible positions complete to isolate tier/precision granularity. Jointly fetched heads may have similar access histories; improvements are not guaranteed. Measure serialization/metadata/RPC overhead too.

**Exit:** per-head segmentation is correct, and its quality, latency, and resource effects are measured against the current-granularity baseline.
